## Phase 5-1: Kling AI 영상 자동 생성

### 설계 결정

**단일 클립 vs 체인 클립 분기**
- `duration ≤ 10초` → `generateSingleClip()`: Kling API 1회 호출, CDN URL 반환
- `duration > 10초` → `generateVideoChain()`: Claude Haiku 장면 분할 → 순차 클립 생성 → FFmpeg concat

체인 방식을 선택한 이유: Kling v2는 최대 10초 클립만 지원. 20초/60초를 하나의 프롬프트로 생성하면 내러티브 일관성이 깨짐. 장면별 분할 프롬프트가 시각적 연속성을 더 잘 유지함.

### SSRF 방어

`assertKlingUrl(url)` 헬퍼를 `generateSingleClip` 반환 직전과 `downloadToFile` 시작에서 모두 호출:

```typescript
const ALLOWED_KLING_HOSTS = ['.klingai.com', '.kling-cdn.com'];

function assertKlingUrl(url: string): void {
  const parsed = new URL(url);
  if (parsed.protocol !== 'https:' ||
      !ALLOWED_KLING_HOSTS.some(h => parsed.hostname.endsWith(h))) {
    throw new Error(`허용되지 않는 다운로드 도메인: ${parsed.hostname}`);
  }
}
```

초기 구현에서는 `downloadToFile`에만 있었지만, 단일 클립(5s/10s)은 URL을 직접 반환하고 다운로드하지 않기 때문에 SSRF 검증이 누락됐었음. `generateSingleClip` 내부에서도 URL 검증 추가.

## Phase 5-3: AI Attribution Engine

  channels[channels.length - 1].attributionPct = Math.max(0, 100 - sumExLast);
}

INSERT INTO cdp_identity_index (hash, type, profile_id, mission_id, id_class, confidence, created_at)

### 문제: klingService 타임아웃 테스트의 UnhandledPromiseRejection

```
(node) PromiseRejectionHandledWarning: Promise rejection was handled asynchronously
```

`jest.advanceTimersByTimeAsync(330_000)` 완료 후 promise가 reject됐는데, 핸들러를 나중에 붙이면 Node가 이미 "unhandled"로 마킹함.

**해결 방법**: `.catch()` 즉시 붙이기

```typescript
// 이전 (경고 발생):
const promise = generateVideoKling('test', '9:16', '5');
await jest.advanceTimersByTimeAsync(330_000);
await expect(promise).rejects.toThrow('타임아웃'); // too late

// 수정 후:
let caught: unknown;
const done = generateVideoKling('test', '9:16', '5').catch(e => { caught = e; });
await jest.advanceTimersByTimeAsync(330_000);
jest.useRealTimers();
await done;
expect((caught as Error).message).toContain('타임아웃');
```
