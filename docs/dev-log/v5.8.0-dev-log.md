## 수정 내역

### 1. 내부 API 키 랜덤 생성 (main.js)

**파일**: `electron/main.js` — `startBackend()` 함수

**이전 코드 (문제)**:
```js
return process.env.OOMNI_INTERNAL_API_KEY ?? 'oomni-internal-dev-key-change-me!'
```
프로덕션 환경에서 env가 설정되지 않으면 예측 가능한 문자열이 내부 API 키로 사용됨.

**수정 후**:
```js
if (!process.env.OOMNI_INTERNAL_API_KEY || process.env.OOMNI_INTERNAL_API_KEY === 'oomni-internal-dev-key-change-me!') {
  process.env.OOMNI_INTERNAL_API_KEY = require('crypto').randomUUID()
}
```
- 앱 시작마다 UUID v4 자동 생성
- 재시작 간 키가 달라짐 → 탈취된 키 재사용 불가
- 개발 모드 `.env` 파일의 키가 있으면 그것을 사용 (기존 개발 흐름 유지)

### 2. OpsCenter.tsx — fallback 'dev-key' 제거

**파일**: `frontend/src/pages/OpsCenter.tsx`

**이전**:
```typescript
let internalKey = 'dev-key'
try {
  internalKey = await window.electronAPI?.getInternalApiKey?.() ?? 'dev-key'
} catch { /* noop */ }
```

**수정 후**:
```typescript
const internalKey = await window.electronAPI?.getInternalApiKey?.() ?? ''
if (!internalKey) throw new Error('내부 API 키를 가져올 수 없습니다')
```
- 키 획득 실패 시 명시적 에러 발생 → 사용자에게 연결 오류 메시지 표시
- `'dev-key'` 하드코딩 완전 제거

### 3. Backend 서버 127.0.0.1 명시 바인딩

**파일**: `backend/src/index.ts`

**이전**:
```typescript
server.listen(config.PORT, () => { ... })
```
주소 미명시 시 Node.js 기본값 `0.0.0.0` → 동일 네트워크의 다른 기기에서 접근 가능.

**수정 후**:
```typescript
server.listen(config.PORT, '127.0.0.1', () => { ... })
```
- 로컬호스트에서만 수신 — 외부 네트워크 완전 차단
- Frontend 서버(`127.0.0.1` 바인딩)와 동일한 보안 수준으로 통일

---

### 4. Electron sandbox: true 활성화

**파일**: `electron/main.js` — `BrowserWindow.webPreferences`

**이전**:
```js
sandbox: false,  // preload에서 일부 Node API 필요
```

**수정 후**:
```js
sandbox: true,   // preload는 contextBridge/ipcRenderer만 사용 — sandbox 안전
```

**검토 근거**:
- `preload.js`가 사용하는 API: `contextBridge`, `ipcRenderer` (Electron IPC), `process.platform`
- 위 API들은 모두 Electron 샌드박스 환경에서 정상 동작
- Node.js 빌트인(`fs`, `path`, `require` 등) 미사용 → sandbox 활성화 안전

**효과**:
- renderer 프로세스가 OS 레벨 권한으로 격리됨
- XSS 공격이 발생해도 OS 명령어 실행 불가
